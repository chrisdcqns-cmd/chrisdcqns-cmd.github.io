# OrienRun EPS — notes pour Claude

> Lire d'abord la charte commune : `../CLAUDE.md` (barre, couleurs, écran « Choisis ta classe », accès enseignant caché, listes communes, PDF et auto-positionnement au format Danse/Volley).

Application web (PWA) de course d'orientation pour l'EPS, hébergée sur GitHub Pages (`index.html` à la racine).

- `index.html` : toute l'appli (HTML + CSS + JS). **Modifier directement `index.html`** : `src/` et `build.py` sont obsolètes (index.html a été modifié directement depuis ; relancer build.py effacerait ces changements).
- Rôles : accueil → **Élève** (téléphone) ou **Espace enseignant** (tablette, code `eps` sans script, sinon mot de passe du script vérifié par `teacherCheck`).
- Projet enseignant (carte en dataURL, dessins, balises, parcours, calage GPS) : IndexedDB `orienrun` / clé `projet`. Séances : clés `session:CODE` et `sessions`.
- QR de balise : `URL#b=<numéro>.<code>`. QR de départ : `URL#go=<base64url JSON>` (séance, URL du script, tél. du prof, intervalle GPS, sel, parcours compact avec empreintes des codes : jamais les codes en clair).
- Carte non à l'échelle : `makeGeoref()` = transformation affine + correction locale (pondération inverse à la distance) à partir des points de calage et des balises géolocalisées et placées.
- Symboles : tableau `SYM` (codes ISOM 2017-2 / ISSprOM 2019), surimpression violette `VIOLET`.
- `apps-script/Code.gs` : actions `push` (élève), `getSession` (carte), `publish`, `poll`, `decide`, `msg`, `teacherCheck` (prof). Onglets : Seances, Evenements, Decisions, Messages.
- SMS de secours : format `OR1;S=…;C=…;R=…;N=…;K=…;D=<départ s>;P=<n>+<s>,…;F=<s>;G=lat,lon` (`parseSMS` / `smsResultat`).
- Interface et textes en français ; utilisateurs : lycéens (classes TMELEC, TTBMA, 1GT…) et leur enseignant d'EPS. Pas de noms d'élèves dans le dépôt public.
- `sw.js` : changer `CORE` (orienrun-core-vN) si on ajoute des fichiers à `CORE_FILES`.
- Accès enseignant (`profLogin`, src/teacher.js) et changement de code (src/teacher3.js) : pavé `epsPin()` (copie de celui d'`eps-home.js`, touche ABC pour les lettres), jamais de champ texte. (modifier `index.html`, voir plus haut).
- Bilans de la leçon : bouton « 🗜️ Bilans (.zip) » des résultats → `zipBilans(X)` / `orienPdf` (src/teacher3.js, avec `EPDF`, PDF + zip maison) ; un sous-dossier par classe si la leçon en mélange plusieurs.
- Bibliothèque de leçons : onglet « 📚 Bibliothèque » (src/biblio.js) : `BIBLIO` (cycle de 10 leçons + situations courtes, format fiche de leçon EPS, AFLP bac pro / AFL bac GT du CA2), leçons perso dans IndexedDB clé `biblio`, `courseFromLecon()` crée un parcours préréglé (`o`).
- Mode enseignant partagé (`eps.teach.until`) : `profLogin` sans code si actif ; mot de passe du script retenu sur la tablette (`localStorage['orienrun.tpw']`) après la 1re saisie.
- Appli Terrain (iPhone) : dossier `../terrain/` (page unique, sans build) : pose de balises à position GPS contrôlée (mesure moyennée, refus si imprécis), photos, tracé de chemins avec pause automatique, exports (JSON `orienrun-terrain`, GPX, calque 1:25 000/1:50 000 avec quadrillage UTM). Import dans OrienRun : src/terrainimp.js (`importTerrain`, chemins en attente dans `P.gpsTraces` tant que la carte n'est pas calée, `convertTraces`).
- Terrain v2 : un point tous les `CFG.pas` m (3 par défaut), repères (`REP`, mesurés comme les balises), calage de la trace sur photo aérienne (`CAL` = paires src→dst, `makeCorr` : 1 point décalage, 2 similitude, 3+ affine + IDW ; `cp()` applique la correction aux exports et à l'affichage), export CSV point par point avec UTM. OrienRun : les repères importés deviennent des points de calage sans position sur la carte (`P.calib` avec `x == null`) à placer (`placeReperes`, `ED.placeCal`) ; les chemins importés gardent leurs points GPS (`f.gps`) et sont redessinés par `recalTraces()` après chaque nouveau calage.

## Terrain v3 : densité, zones, éléments, carte à l'échelle (nov. 2026)
- Appli Terrain : types LINES (lignes ISOM) / ZONES (surfaces, fermées à l'arrêt). Pendant un tracé de ligne, boutons densité gauche/droite (DENS : blanc, vert1-3, jaune, jclair) → chaque point porte `g`/`d` ; largeur `CFG.bande` (m, réglages). `densBands()` → polygones (chemin + parallèle décalée). Éléments ponctuels `ELT` (DB "elements", `elementSheet()`, mesure 6 s), utilisables aussi comme points de calage sur photo. Export JSON v2 + `elements` (rawLat/rawLon), points avec g/d, `zone`.
- OrienRun `terrainimp.js` : `convertTraces` crée zones (area, `f.gps`), bandes de densité (`DENS_SYM`, `f.dens`), chemins ; `convertElts` → points avec `f.gpsPt` ; en attente sans calage : `P.gpsTraces` (avec g/d/bande) et `P.gpsElts`. `recalTraces` gère gps et gpsPt.
- Carte vierge à l'échelle : `blankMapDialog`/`makeBlankMap` → `P.map.{scale, pxmm (px par mm), frame {west,north,kx,ky,mpp}, under {z,tiles}, showUnder}`, `sym` réglé pour que mapMM = pxmm ; calage auto (5 points `auto:true`, masqués). `dropScale()` quand on charge une image ou une feuille blanche. Photo IGN (ORTHOIMAGERY.ORTHOPHOTOS, WMTS PM) via `underlaySVG`, rendue seulement si `mapSVG(..., {under:true})` (éditeur) — jamais imprimée ni côté élève.
- Outil « Mesurer une distance » (`ED.meas`, `mapDist`). `printCourse` imprime à la taille exacte avec barre d'échelle si la carte tient dans la page.
- Apparence des postes (onglet Carte, « Apparence des postes ») : `P.map.circ` (taille des cercles), `P.map.txt` (numéros et codes), `P.map.showCode` 0 = non, 1 = éditeur et carte générale (sans parcours), 2 = aussi parcours imprimés. `overprintSVG` écrit le code en violet sous le numéro ; `mapSVG(..., {noCode:true})` côté élève (jamais de code sur l'appli élève).
- src/cartes.js : rubrique « Ma carte » (onglet Carte). `downloadDialog` : PNG (`mapImage(proj, ver)`, rendu SVG→canvas) ou impression, versions `MAP_VERSIONS` eleve (numéros sans code) / vierge (`noNum`, cercles seuls) / prof (codes). Bibliothèque de cartes sur l'appareil : IndexedDB `cartes` (liste {id,nom,date,thumb,n}) + `carte:<id>` (copie complète de P), `P.libId` ; export/import JSON `orienrun-cartes`. `coeDialog(proj)` envoie la carte (JPEG) + balises {n,code} vers l'appli CO éval via `coeSave` (conf lue par `coeGet`, obligatoires/nb ajustés).
- Appli `../co-eval/` (CO – préparation à l'évaluation, page unique) : 2 parcours ([0] individuel, [1] collectif, `fixConf`), binôme choisi à l'identification (`ME.binome`). Progression sauvegardée en ligne (`coeState`, onglet CO_Etat, `packLive`/`unpackLive`, champ `u` = dernière modification, `runSig`) : reprise en choisissant son nom, partage du collectif entre les deux téléphones (pilote = téléphone qui saisit, l'autre en `vFollow`), balises interdites (`forbidden(k)` : obligatoire de l'autre parcours, individuel du binôme). `coeGet` renvoie aussi les états demandés (`ids`). Enseignant : onglet Suivi (`coeAllStates`, Leaflet + IGN, position GPS à chaque balise), erreurs des téléphones dans CO_Log (`coeLog`).

- 🆕 Nouvelle carte (`newMapDialog`, onglet Séquence et onglet Carte) : copie du projet sans balises (`type C`) ni parcours, départ/arrivée gardés au choix, nouveau `salt`, balises géolocalisées converties en points de calage ; l'ancienne carte est d'abord rangée dans la bibliothèque (`libSave`).
- CO éval : 👁 Vue élève (bouton de l'espace enseignant) = `index.html?vue=eleve&sim=1` dans un cadre : `SIM`, stockage `coesim.` / clés IDB `sim:`, `simApi` (aucun appel réseau, paramètres lus dans `coe.conf` de la tablette, classe fictive `SIM_CL`), horloge décalée (`coesim.off`, ⏩), barre jaune avec le code de la balise attendue, `simReset()`.
- CO éval, nov. 2026 : **1 à 4 parcours** (`C.pv = 2`, `fixConf`, `MAXP`, `isDuoK(k)`, `duoKs()`, `fitRuns()` ; anciennes confs sans `pv` = [individuel, collectif]). Balise obligatoire facultative (`oblig` vide), `C.noPen` = sans pénalités.
- **Évaluations** : `C.ev = {id, nom, date, cls:["prof|classe"]}` ; un parcours commencé avant `C.ev.date` appartient à une évaluation sauvegardée (`isDeleted`/`canRedo` via `evStart()`, `evCheck()` remet l'élève à zéro, binôme compris, ou le renvoie à l'identification si sa classe n'est pas concernée). Sauvegardes : clé `arch` de CO_Eval (`coeSave` / `coeLoad`, + `carte_<id>`), copie locale `coe.arch` ; consultation en lecture seule par `archOn(a)` / `archOff()` (`VIEW`, `C_LIVE`, `C.evEnd`).
- Impressions (`printDoc`) : `printCodes` (tableau A4), `printBalises(arch)` (trace : balises, codes, nombre de choix, carte avec codes), `paperDialog` (carton papier par parcours) et `paperEntry` (saisie d'un résultat papier : `punch`, `ress.papier`).
- `apps-script/Code.gs` : à redéployer (Nouvelle version) après ces changements : actions `coeLoad`, clés `arch` et `carte_<id>`.
- Niveaux de difficulté : balise `niv` 1-3 (OrienRun : case « Niveau de difficulté » dans la fiche de la balise, envoyé à CO éval qui active `C.niv`). CO éval : `nivOf`, `ptsOf`, `nivSVG` (étoiles sur la carte élève), `p.pts` = points à viser, `analyse().pts` (balises validées).
