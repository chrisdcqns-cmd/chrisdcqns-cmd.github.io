# Danse EPS — notes pour Claude

> Lire d'abord la charte commune : `../CLAUDE.md` (barre, couleurs, écran « Choisis ta classe », accès enseignant caché, listes communes, PDF et auto-positionnement au format Danse/Volley).

Application web pour tablette (danse, CA3, lycée), hébergée sur GitHub Pages : `danse/index.html` contient tout. Les 3 premiers `<script>` sont des bibliothèques intégrées pour le hors ligne (pdf-lib, JSZip, générateur QR de Kazuhiko Arase) ; le 4e est le code de l'application (lisible) ; le 5e charge `../eps-home.js`.

- Données dans `localStorage`, clé `danse-eps-v1` : `{reglages, grilleNom, criteres:[{id:'afl1'|'afl2'|'afl3', court, titre, sous, titreEleve, d:[4 textes enseignant], e:[4 textes élève], poids}], classes:[{id,nom,eleves:[{id,nom,prenom,groupeId,ev:{afl1:{d,pos}},comm,statut,auto}],groupes:[{id,nom,theme}]}], classeId, obs:[…]}`.
- Grilles prêtes : `GRILLES.origine` (Additio 12/4/4 ; AFL1 = composer **et danser** : mémorisation, concentration, présence, `grilleV: 2` met à jour les tablettes) et `GRILLES.court` (cycle court 10/5/5).
- Points : bandeaux des degrés en % (`reglages.bandes`, D1 0-25, D2 25-50, D3 50-75, D4 75-100) ; `pos` (0-1) = position dans le bandeau ; au clic, valeur Additio exacte (`def` : 15/45/75/100 %), le curseur se cale au 0,25 pt (`nSteps`). Note /20 = somme ramenée sur 20, arrondi `reglages.arrondi`.
- Code enseignant : le même que les autres applis (`relais-vitesse-code-v1`, `eps.teach.until`, pavé `epsPin`). Vues enseignant (`TEACH`) : evaluation, bilan, classe, reglages. Vues élève sans code : observation, procedes, eleve.
- Auto-positionnement : seulement si `reglages.autoOuvert` et date ≤ `reglages.autoJusqua`. Lien nominatif `…/danse/#eleve=<base64url de [nom, prénom, classe, grille, AAAAMMJJ]>` (QR + lien cliquable sur le PDF élève). Si une boîte de dépôt est disponible (script commun à jour, sinon ancien script de Danse `reglages.envoiUrl` + `reglages.envoiCle`), le lien contient aussi `[…, idDépôt, cléAES, idScript]` : id = HMAC(clé secrète, `dan|id|classe|nom|prénom`) (12 octets), clé = HMAC(clé secrète, `dan|k|`+id) (16 octets). Le téléphone chiffre (AES-GCM) et POST `{drop:{k:'dan|'+id, x}}` au script (sans clé), puis vérifie par JSONP `dropchk`. Les tablettes relèvent `?key=…&drops=1&since=S.dropSeq` (vues enseignant, toutes les 30 s). Repli : code `DANSE1.<base64url>` à coller dans « Classe & auto-positionnement ». Script : `danse/apps-script/Code.gs` (`dropPush_`, `dropCheck_`, `dropPull_`, `ping` pour le test, `purge` avec la clé ; onglet « Depot ») ; guide : `danse/apps-script/README.md`.
- Auto-positionnement **pas à pas** (`UI.em.step` : 0 = nom, 1…N = un critère par écran, N+1 = mots + récapitulatif cliquable). Sur tablette, choisir un nom qui a déjà `e.auto` demande confirmation (« Ce n'est pas moi »). Même règle dans `eps-eval.js` (`P.step`) et Volley (`APE.step`, `apStep`, `apQui`).
- Ouverture par classe : `reglages.autoCl = {idClasse: AAAA-MM-JJ}` (écran « Quelle classe ? », `apCarte`, `autoClasse(cl, jours|null)`) ; `autoFin(cl)` / `autoOuvert(cl)` (défaut : classe courante) combinent l'ouverture générale et celle de la classe ; date limite du lien = `autoFin(cl)`.
- Boîte de dépôt : `boiteDepot()` → `EPSD.boite(null)` d'eps-home.js (script commun si `eps.share.dropv` = 1, sinon ancien script de Danse `reglages.envoiUrl/envoiCle`). `releverDepots` relève **toutes** les sources (`S.dropSeqs[id]`), l'ancien script compris tant qu'il est réglé (liens déjà distribués).
- Évaluation rapide : `UI.evMode` = 'eleve' | 'crit' (`UI.evCrit`) | 'groupe' (`UI.evGrp`) → `rRapide()`, contrôle compact `miniCtl(c, e)` ; « même degré pour tout le groupe » (`data-gall`) ne touche ni absents ni dispensés.
- Banque de commentaires : `COMMS` (EPSP `comms`), puces `data-cb` sous `#comm` (ajout / retrait).
- Carnet de chorégraphie : `groupe.carnet = {titre, intention, procedes[], relations[], debut, milieu, fin, musique, maj}` (synchronisé avec la classe) ; vue `carnet` (élève en mode classe et enseignant via 📚 Bibliothèque), résumé dans la fiche d'évaluation.
- Observation : groupes en gros boutons (`#oGrp`), puces agrandies ; après « Valider », écran de retour au groupe observé (`UI.retour`, `rRetour`).
- Réglages : `verifs()` / `verifHTML()` / `bindVerif()` = ✅ liste de vérification en tête.
- Renommer une classe (`renommerClasse`) appelle `EPSD.renameClass(ancien, nouveau)` : liste commune (champ `old`) et dispenses suivent, sans doublon.
- Côté élève (sans lien nominatif), `UI.mode` : `'res'` = ressources ouvertes depuis l'écran commun « Choisis ta classe » → seule la vue `procedes` est accessible (classe `res-mode` sur body) ; `'cl'` = classe choisie (écran commun, ou tablette verrouillée par l'enseignant). L'auto-positionnement sur tablette exige `UI.mode === 'cl'` et un nom choisi dans la liste (plus de saisie libre « je ne suis pas dans la liste »).
- Lien personnel (`#eleve=<jeton>`) : `LIEN` mémorisé dans `sessionStorage` (`danse.lien`) ; tant qu'il n'y a pas de code enseignant, `route()` ramène toujours à l'auto-positionnement de cet élève (même si l'adresse change) et `body.lien-mode` masque onglets, bouton Enseignant, Accueil et boutons communs. Volley-ball fait de même (`volley.lien`, `body.apmode`).
- PDF élève : `pageEleve()` (paysage, ajuste la taille du texte), récapitulatif `recapBytes()`, zip `Danse_<classe>_<jj-mm-aaaa>.zip`.
- Interface et textes en français, tutoiement des élèves. Aucun nom d'élève dans le dépôt public.
- Synchronisation entre appareils (script commun, `eps.share.v1`) : enregistrements chiffrés `danse|cfg`, `danse|cl|<id>`, `danse|el|<id>` (élève avec `classeId`), `danse|ob|<id>` (PBKDF2 sel `danse-eps-sync-v1`). État local `danse-eps-sync-v1` {since, h (empreintes), u (horodatages connus), p (à envoyer), ch, init}. `syScan()` repère les changements ; `synchroniser()` reçoit puis envoie (au démarrage, 5 s après une modification, toutes les 60 s). Premier passage sur un appareil : horodatage 2 → fusion (`syAppliquer`, classes et élèves reconnus par leur nom, degrés réunis). Sinon le plus récent l'emporte, élément par élément.
