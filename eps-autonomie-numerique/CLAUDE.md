# EPS · Autonomie et numérique — charte commune (à lire avant toute modification)

Ces règles valent pour **toutes** les applications du dossier (CCF, Escalade, OrienRun, Relais Vitesse, Volley-ball, Badminton, Danse, CO-Évaluation, Appel AS, EDT, Pose des balises) **et pour toute nouvelle application**. Elles ont été fixées par l'enseignant (seul utilisateur, lycée, plusieurs tablettes). Quand une amélioration est faite dans une appli, se demander si elle doit être reportée dans les autres et dans ce fichier. Les notes propres à chaque appli sont dans `<appli>/CLAUDE.md`.

## Langue et vocabulaire
- Tout en français. Élèves tutoyés. Dire « leçon » (jamais « séance ») et « séquence » (jamais « cycle »).
- Aucun nom d'élève dans le dépôt public : les listes restent sur les tablettes (localStorage / IndexedDB) et dans les Google Sheets ; ce qui part en ligne est chiffré (AES-GCM, clé secrète du partage).

## Structure d'une appli
- Un dossier `<appli>/` avec un `index.html` autonome (bibliothèques intégrées pour le hors ligne : pdf-lib, JSZip, QR…).
- En tête, **synchrone**, avant le script de l'appli : `<script src="../eps-lists.js"></script>` (listes de classes communes).
- À la fin : `<script src="../eps-home.js" defer></script>` (réglages, code enseignant, dispenses, écran de classe, boutons communs, synchro des listes).
- Tuile sur l'accueil `index.html` (section « Activités », ou « Outils enseignant » avec `data-eps-teach`), couleur et icône de l'appli.
- Mettre à jour `/sw.js` (`CORE` +1, fichiers à mettre en cache) et le `sw.js` propre à l'appli s'il existe, pour que ⟳ sur les tablettes récupère la nouvelle version.
- Code enseignant commun (pavé `epsPin`, `eps.teach.until`, code `relais-vitesse-code-v1`) ; réglages communs `EPSR.get()` (établissement, enseignant, année…), partagés entre tablettes.

## Espace enseignant (commun)
- `eps-shell.js` : `EPST.init({app, nom, color, isTeacher, anchor, main, tabs:{seq, eval, cls, bil}, biblio:[…], reglages:[…]})` ; onglets toujours dans cet ordre : 📅 Séquence · 👁 Vue élève · 📚 Bibliothèque · 📋 Évaluation · 👥 Classe · 📄 Bilans · ⚙ Réglages. On arrive sur Séquence. Pas d'appli « élève avec des cases enseignant ».
- **Tout est paramétrable** : toute valeur ou liste figée dans une appli (messages, raisons, rôles, intitulés, thèmes de travail, durées, seuils…) se déclare avec `EPSP.p({id, sec, label, type:'list'|'text'|'number', def, fixed, aide})` (eps-lists.js) ; elle apparaît alors dans ⚙ Réglages → 🎛 Paramètres de l'appli (eps-shell.js), synchronisée (`eps.param.v1`, `pa|`). `fixed` = nombre de lignes imposé quand l'ordre porte du sens (renommer seulement). Ne jamais changer les clés internes, seulement les intitulés (helper `PRM(id, sec, label, clés, intitulés)` dans Volley et Badminton). Fait : Escalade, Volley-ball, Badminton, Danse, Acrosport, OrienRun, Relais Vitesse (la CCF a déjà son éditeur de protocole).
- Fiche d'utilisation (Réglages → 📖) : `eps-guides.js`, à mettre à jour à chaque nouvelle fonction ou nouvelle appli.
- OrienRun utilise aussi `EPST.init` (`EPSTORI`, ancre `#prof header`, `#ptabs` masqués) : ses onglets propres sont rangés dans les onglets communs. Toutes les applis d'activité ont donc les mêmes 7 onglets.
- Vue élève : l'appli dans un cadre `?vue=eleve` (mode enseignant ignoré par `eps-lists.js`), sans quitter le mode enseignant.
- Claude (API, par le script commun, clé `ANTHROPIC_KEY` côté serveur) : ✨ Reformuler / 🎤 Dicter sur tout `textarea[data-eps-comment]`, version élève d'une grille (`eps-eval.js` ; éditeurs propres de Volley, Badminton, Danse : `EPSD.versionEleve(bouton, descripteurs, champs, enregistrer)`), consigne simplifiée ou traduite (Bibliothèque). Jamais de nom d'élève envoyé ; tout ce qui va aux élèves est relu et validé par l'enseignant.

- **Leçons communes** `eps-lecons.js` (chargé par `eps-home.js` dans toute appli d'activité ; ajouter le dossier de toute nouvelle appli d'activité dans le test de `eps-home.js` et dans `APPS` d'`eps-lecons.js`) : `EPSLC.actions()` ajoutées à l'onglet Séquence et `EPSLC.biblio()` à la Bibliothèque par `eps-shell.js` ; une appli sans espace commun appelle `EPSLC.open('lec'|'docs'|'live')`.
  - Structure de leçon de l'enseignant (ne pas la changer) : objectifs moteur / méthodologique / social, but, dispositif, matériel, échauffement (consigne, schéma), situations (consigne, schéma, critères de réussite quantitatifs / qualitatifs, critères de réalisation, variables simplification / complexification), remise en action, bilan.
  - Claude s'appuie **en priorité sur les documents déposés** par l'enseignant (sa séquence) ; il ne propose du nouveau que pour combler un manque ou sur demande (séquence parallèle plus simple / plus difficile / variante). Toute proposition est un **brouillon** (`statut:"brouillon"`, champs `ai` en jaune) : jamais montré aux élèves ni programmable avant « ✓ Valider ».
  - Leçon programmée (compte à rebours, ouverture automatique), leçon en cours (messages en grand avec son, minuteur, étape, rangement par groupes avec trace commune `eps.rang.v1` et rotation). Pas d'appel ni de dispensés dans la leçon (l'appel se fait sur Pronote).
  - Données synchronisées par `EPSD.store` (`lc.<appli>|`, `li.` schémas, `ld.` documents découpés en morceaux de 26 000 caractères, `lv.` leçon en cours relevée toutes les 6 s par `EPSD.syncOne`, `rg|`). Claude : `EPSD.post({lc:{op:'transcrire'|'lecon', …}})` → `lecon_()` du script commun (modèle `CLAUDE_MODEL_LECON`).

## Mode élève
- En mode élève, l'appli s'ouvre sur l'écran commun « Choisis ta classe » : `(window.EPSG_Q=window.EPSG_Q||[]).push({app, sub, color, icon, classes(), current(), select(id), resources:[{ico,label,sub,open}], teacher(), isTeacher(), when()})`. Les ressources utiles sans classe (dispositif, sécurité, échauffement…) y figurent. Le bouton Accueil de l'appli, côté élève, ramène à cet écran.
- **Aucun bouton « enseignant » visible par les élèves.** Accès enseignant : appui long de 2 s sur le logo (barre, écran de classe, titre des écrans tablette coach / terrain), géré par `eps-home.js` ; l'appli peut fournir `window.epsTeacherEntry()`.

## Classes et élèves (communs à toutes les applis et tablettes)
- Une classe importée n'importe où (accueil ou appli) apparaît partout. Toute appli qui gère des classes s'inscrit dans `APPS` de `eps-lists.js` (`key, list, nom, names, make, add, del, data`) et fournit `window.epsListsHook = {save, reload}` pour la mise à jour en direct.
- Activités par classe (Réglages → Listes d'élèves) : champ `off` de la liste commune, déduit de l'emploi du temps (`edtApply()` d'`eps-home.js`, enseignant `eps.edt.moi`) sauf si choisi à la main (`man:1`, prioritaire) ; une classe non attribuée à l'activité n'y apparaît pas. Suppression (double confirmation) et fusion de listes : dans Réglages.
- Ne jamais effacer une classe ou un élève qui a déjà des données (évaluations, grimpes, courses).
- `window.epsCurrentClass()` → `{nom, eleves}` doit renvoyer la classe **réellement choisie**, en mode enseignant comme élève (Escalade : `CF.sel` ; Acrosport : `lessonClass` ; CCF : `T.cls`). Les onglets communs (Évaluation, Bilans) passent `(epsCurrentClass()||{}).nom` à `mount`, jamais une variable propre à l'appli. `EPSE.store` garde la dernière classe choisie (`eps.eval.cls.<app>`) au lieu de retomber sur la première.
- `window.epsCurrentClass()` → `{nom, eleves}` : la pastille des dispensés ne compte alors que la classe choisie (sinon tous).

## Évaluation, bilans et PDF (modèle : Danse et Volley-ball)
- **Module commun `eps-eval.js`** (`<script src="../eps-eval.js"></script>`) : à utiliser pour toute appli (actuelle ou nouvelle) au lieu de recopier le code de Danse / Volley.
  - Appli qui a déjà sa propre évaluation : `EPSE.create(adaptateur)` (Badminton, Relais Vitesse) ; afficher `exportsHtml()` + `card(classe)` dans le bilan puis `bindExports` / `bindCard`.
  - Appli sans évaluation : `EPSE.store({app, nom, ca, color, icon, pfx, code, url, grid, isTeacher, unlock})` (Escalade, Acrosport, OrienRun) ; option `groups(classe)` → `[{nom, membres:["Prénom NOM"…]}]` : élèves rangés par groupe enregistré dans Évaluer (Acrosport), « Sans groupe » à la fin : écran complet Évaluer / Bilan & export / Grille ouvert par `.open(classe)` depuis un bouton enseignant ; classes = listes communes attribuées à l'activité ; données `eps.eval.<app>.v1` synchronisées par `EPSD.store` (eps-home.js).
  - Import de grille : Évaluation → Grille → 📥 (PDF, Excel/CSV, photo, souvent Additio) → `lecon_({op:'grille'})` du script commun → aperçu puis remplacement après confirmation.
  - Lien élève `…/<appli>/#auto=<jeton>`, préfixe de dépôt de 2 lettres propre à l'appli (`pfx`), code de repli `<CODE>.…`. Bibliothèques partagées dans `vendor/` (pdf-lib, JSZip, QR), chargées au premier export.
- En-tête commun des bilans : `EPSR.pdfHead(doc, {act, titre, ca, ac, nom, classe, lecon…})` / `EPSR.htmlHead(...)` : bandeau `#14171C`, filet à la couleur de l'appli, établissement, enseignant, classe, date.
- Fiches élèves au format Danse/Volley : pdf-lib, une fiche par élève (paysage, texte ajusté), un PDF ou un .zip `<Appli>_<classe>_<jj-mm-aaaa>.zip` avec récapitulatif de classe.
- Auto-positionnement de l'élève (si l'activité a une grille par degrés) : QR code + lien nominatif sur la fiche (`…/<appli>/#eleve=<jeton>`), envoi chiffré au dépôt (script de Danse), code de repli à coller, mode lien qui masque tout le reste, sur tablette seulement après le choix de la classe et du nom dans la liste ; positionnement de l'élève affiché à côté de celui de l'enseignant, et suivi dans Bilan & export. Voir `danse/CLAUDE.md` et `volley/index.html`.
- **Pastille 🙋 commune** : dans l'onglet Évaluation de chaque appli (liste des élèves et en-tête de la fiche), `window.epsApChip({nom, date, crit:[{l, p, e}], r, m})` (eps-lists.js) ; un appui ouvre la bulle d'eps-home.js (degrés prof / élève, ▲▼, « réussi » / « à améliorer ») sans ouvrir la fiche. `M.apChip(E)` dans eps-eval.js, `apChipVol` (Volley), `apChipDan` (Danse), `apChipRel` (Relais, qui recueille aussi `r` / `m` sur la tablette élève). Toute nouvelle appli évaluée doit l'afficher et recueillir les deux commentaires de l'élève.
- Curseur intra-degré (position dans le degré, note au 0,25 pt), comme Danse et Volley.
- **Bilans en ligne** : bouton `🌐 Publier en ligne` d'`exportsHtml` → `EPSD.publish({app, nom, color, classe, eleves:[{full, bytes()}]})` (eps-home.js). Code élève de 6 caractères commun à toutes les applis (`eps.codes.v1`, synchronisé `cd|`), fiche PDF chiffrée avec le code (SHA-256 → identifiant, PBKDF2 150 000 + AES-GCM), déposée par `doPost {bil:{put,del}}` (feuille « Bilans ») ; page élève `mon-bilan/#s=<id du script>` (`doGet ?bil=<empreinte>`, sans clé). Volley (`publierEnLigne()`) et Danse (`#xPub`) branchés sur leur `pdfEleveBytes`.
- **Export Pronote** dans le bilan de chaque appli notée : `EPSR.pronote({app, classe, color, cols:[{t:'Note /20'}, …], rows:[{nom, prenom, st, v:[…]}]})` (eps-home.js) : ordre alphabétique de Pronote (NOM puis prénom), virgule décimale, codes A (absent) / D (dispensé, inapte) / N (non noté), copie de la colonne à coller dans le devoir, copie de toutes les colonnes, fichier .csv pour l'import du Client PRONOTE. Déjà branché dans `eps-eval.js` (bouton 📋 Pronote de `exportsHtml`), Danse et Volley (note /20 + une colonne par AFL).

## Synchronisation entre tablettes
- Classe de démonstration (Réglages communs, eps-home.js `demoCreate` / `demoRemove`) : liste `DÉMO (fictive)` marquée `demo:1` (retirée des applis même avec des données), fiches `demo-<appli>`, observations `demo-…`, évaluations semées par `EPSE.store` (`demoSeed`, drapeau `eps.demo.v1`). Toute nouvelle donnée liée à une classe doit porter le nom de classe (`c` ou `cls`) pour être effacée au retrait.
- **🧪 Simulation (bac à sable)** : `EPSD.sim.enter/exit` (eps-home.js). Instantané de tout le localStorage + base IndexedDB « orienrun » dans IndexedDB « eps-sim », drapeau `eps.sim.v1`, garde d'eps-lists.js (`window.EPS_SIM`) qui bloque fetch / XHR / JSONP / sendBeacon vers Google sauf les demandes à Claude (`ai=`, `lc`, `aiReq`) ; `sync()` ne fait rien ; bandeau `#eps-simbar` (passer élève / enseignant, quitter). Toute page doit charger eps-lists.js en premier dans `<head>` (garde). Tout nouvel envoi réseau d'une appli passe par fetch/XHR/script pour être bloqué.
- Séparation enseignant / élève : en mode élève, l'écran enseignant ne doit pas être seulement recouvert mais masqué (Volley, Badminton : `html:not(.eps-teach) body>header, body>main {visibility:hidden}`). Aucun bouton « Code enseignant » / « 🔒 Enseignant » côté élève (Appel AS excepté : outil enseignant).
- 🧪 Leçon simulée : action de l'onglet Séquence (`EPSLC.actions()`), `EPSD.demo.{on,create,nom}` ; lance la fiche `demo-<appli>` sur la classe fictive et ouvre le pilotage (bouton 👁 Voir côté élève → `EPST.openVue()`).
- Réponses du script commun : JSON envoyé en ASCII (`asc_`, accents en \uXXXX) et textes de Claude nettoyés (`propre_`) ; balise JSONP en `charset=utf-8`. Ne pas revenir en arrière (sinon « Ã© » illisibles sur certaines tablettes).
- 🔊 lecture des consignes côté élève : `speechSynthesis` fr-FR dans la fiche de leçon élève (eps-lecons.js), rien n'est envoyé.
- Observations dictées `eps-obs.js` (chargé par eps-home.js dans les applis d'activité, mode enseignant) : bouton 🎙, reconnaissance vocale fr-FR, élève trouvé par le prénom (+ initiale ou nom en cas d'homonymes) dans la liste commune, rangé dans `eps.obs.v1` (`ob|`, {app, cls, el, txt, day}) ; traces éditables ; ✨ Condenser = `reformuler(…, {mode:'obs'})` prénoms remplacés par « un camarade » ; `EPSOB.of(nom, classe)` pour la recherche et le bulletin.
- Recherche d'élève `#eps-find` / `EPSD.search()` (eps-home.js, mode enseignant) : lit les listes communes, les dispenses et les magasins `eps.eval.<app>.v1`.
- Appréciations de bulletin `EPSD.bulletin()` (depuis la recherche 🔍) : `reformuler(…, {mode:'bulletin'})` élève par élève à partir d'`evalsOf()`, sans nom ; relecture et ✓ obligatoires avant copie ; `eps.bulletin.v1` local.
- Sauvegarde Drive hebdomadaire : `installerSauvegarde()` / `sauvegardeHebdo()` du script commun (copie du tableur, dossier « Sauvegardes EPS », 10 gardées) ; `doGet` renvoie `sauv` (date de la dernière) → ⚠ sur la pastille si absente ou > 9 jours.
- Pastille d'état `#eps-sync` (eps-home.js, mode enseignant, dans `[data-eps-bar]`) : ✓ / ⏳ / ⚠ / ○ ; tout nouveau magasin passe par `EPSD.store` pour y être compté.
- Script Google commun (`apps-script/Code.gs`, `eps.share.v1`) : enregistrements chiffrés `<appli>|…`, envoi peu après chaque modification, relevé régulier ; le plus récent l'emporte, élément par élément. Sauvegarde / restauration dans Réglages.
- Script commun, bilan de leçon par Claude : `doPost` `aiReq:{id,mode:"bilan",act,t}` → `aiReq_`/`bilan_` (Sonnet, clé `ANTHROPIC_KEY`, réponse JSON rangée 6 h dans `CacheService` sous `ai_<id>`) ; `doGet` renvoie toujours `aiv:1` et `aiRes` avec `aiget=<id>`. Les applis n'envoient que des codes E1, E2… à la place des prénoms.

## Avant de publier
- Tester dans un navigateur (élève et enseignant), sans erreur de page ; vérifier l'écran « Choisis ta classe » et la barre.
- `git pull --rebase` avant de pousser (d'autres sessions travaillent en parallèle) ; en cas de conflit sur `/sw.js`, garder le `CORE` le plus haut + 1.
- Mettre à jour `README.md` et ce fichier si une règle commune change.

## CCF (contrôle en cours de formation)
- Appli `ccf/` (tuile sur l'accueil) : une seule appli pour toutes les activités ; on n'ajoute rien du CCF dans les applis d'activité. Protocoles dans `ccf/src/protocoles.js` (`PROTOS['<act>-<voie>']`, voie `pro` | `gt`) : recopier à la lettre les protocoles envoyés par l'enseignant. Voir `ccf/CLAUDE.md`.
- La CCF a aussi les fiches de leçon et la leçon en cours (onglet 📅 Séquence → `EPSLC.open('lec')`) et le bouton 🎙 des observations : `ccf` est dans `APPS` d'eps-lecons.js / eps-obs.js et dans les tests de dossier d'eps-home.js.
- Une appli d'activité peut publier des ressources pour le CCF dans localStorage `eps.res.<code>` = `[{titre, texte, lien, img}]`.
