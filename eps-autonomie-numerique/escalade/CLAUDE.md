# Escalade EPS — notes pour Claude

> Lire d'abord la charte commune : `../CLAUDE.md` (barre, couleurs, écran « Choisis ta classe », accès enseignant caché, listes communes, PDF et auto-positionnement au format Danse/Volley).

Application web pour tablette (escalade en moulinette, lycée), hébergée sur GitHub Pages : `escalade/index.html` contient tout (HTML + CSS + JS, aucune bibliothèque externe : lecture/écriture .xlsx et QR codes faits main).

- Écran de démarrage `S.t='role'` (`roleScr()`) : « Je suis élève » / « Je suis enseignant » (code `CF.pin`). Après « Je suis élève » : choix de la classe (`S.t='pickcl'`, `clsScr()`, `pickCl(id)` → `CF.sea.cl`), « Changer de classe » sur l'accueil élève. Accueil enseignant : tuiles « Leçon du jour et classes » et « Résultats, QR codes et Google Sheets » (`res`).
- Groupe (`S.t='grp'`, `grpScr()`, `tgG`, `okG`) après le choix de la classe : `CF.grp={cl,d,el}` valable le jour même pour la classe ; `grp()` le renvoie. Badges prénom `chip()` (pastille couleur `hue()`), plus aucun champ texte quand une liste existe (saisie au clavier seulement en « Sans liste »). Cordée par badges (`roleIn`, `setRole` déplace un élève d'un rôle à l'autre, `autoRoles` pour un groupe de 3, `swapR`).
- Sac à POF : `F.pofU` Oui/Non puis nombre 1–10 (Non = 0, Oui sans nombre = 1).
- Habillage : couche CSS « granite, magnésie, corde » en fin de `<style>` (tuiles `--c`, badges `.chip`, barre d'étapes `.prog`).
- Leçons (`CF.lec` : `{id,cl,d,cr,req,min}` par classe et par date ; `CF.sea` = copie de la leçon active) : `activate(cl)` au choix de la classe (leçon du jour préparée, sinon créée avec `lastCfg`) ; écran enseignant `setup()` → aujourd'hui / à venir (`newLe`, `editLe`, `lecEdit`, `saveLe`, `delLe`) / précédentes (`S.lv`, `lecView`, `xlLe`). Chaque grimpe porte `lid`. Migration : l'ancienne `CF.sea` devient une leçon.
- Se préparer et assurer : sous-onglets `ech`, `enc`, `ass` ; bloc `{t:'vgs',items:[{ti,sub,v}]}` = vignettes vidéo (vidéo en IndexedDB `v`, `setVg`, `rmVg`, lecture plein écran `playV`) ; migration `CF.m2`. Pas de vidéo tierce dans le dépôt.
- Mes résultats : onglet Bilan (`bilan()`), blocs `diffsBlock`, `rpTile`, `stx`. Cotation : `pickCv`/`pickCd` font défiler vers `#cvres`.
- Tuiles de l'accueil : icônes SVG `TI` / `tIco(k)` dans une pastille blanche `.tib` (couleur de la tuile) à gauche du texte `.tt` ; enseignant en paysage (`.homeW.tm`) : 3 colonnes. Accueil enseignant : « Leçons et classes », « Importer une liste d'élèves » (`impHome` → fiche Nouvelle classe préremplie via `S.imp`), puis les tuiles élèves et « Résultats, QR codes et Google Sheets ».
- Accueil plein écran : `.homeW` (hauteur = `100dvh - --hh`). `window.epsAppHome` (bouton Accueil commun d'`eps-home.js`).
- Parcours : 🔒 Leçon du jour (classe, critères `CRIT` cochés/obligatoires, objectif) → accueil → Renseigner une grimpe (prénom → corde → couleur → confirmation → critères) → Mes résultats / Cotation / Thématiques.
- Vocabulaire : le numéro est celui de la **corde** ; chaque corde porte plusieurs **voies** de couleur (`WDEF` : cotations par corde).
- Hauteur : 0 = 1re dégaine non dépassée, 1–8 = dernière dégaine dépassée, 9 = Top (`TOP`). Voie réussie = Top. Valeur non choisie = `''`.
- Cordée (étape 5, `roles()`, `ROLES`) : `r.asr` assureur et `r.cas` contre-assureur obligatoires, `r.obs` observateur facultatif ; liste de la classe ou « Autre » ; refus si grimpeur = rôle ou assureur = contre-assureur ; gardée par « Autre voie ». Mes résultats compte aussi les rôles tenus.
- Ratio pieds/mains : `RP(p,m)` = pieds ÷ mains si les deux > 0 ; repères `rpLvl` (< 1 rouge, < 1,5 orange, sinon vert), affiché en direct sous « Prises de pieds » (`#rpm`, `upR()`), à l'écran « Grimpe enregistrée », dans Mes résultats (total pieds ÷ total mains) et en colonne Excel / Sheets v3 (pas dans l'ancien format 16 colonnes).
- Stockage `localStorage` avec le préfixe `escalade.` (clés `c` contenu, `w` cotations, `r` grimpes, `cf` réglages/leçon `cf.sea`, `cl` classes, `sh` Google Sheets). Vidéos dans IndexedDB `esc`.
- Code enseignant : `cf.pin` (défaut 1234) ; mode prof `S.T`. Saisie uniquement avec le pavé `epsPin()` (copie intégrée, identique à celle d'`eps-home.js`) : jamais de champ texte ni de clavier du système, aucun caractère affiché.
- Hauteur : premier critère, juste après la cordée. 0 (`low()`) = ligne rouge (3 m) non dépassée : message `.redl`, les autres critères se ferment, « Pourquoi ? » obligatoire (`WHY`, `whyBox`, précision `F.whyT`) → champ `r.why` (Mes résultats, Excel, Sheets v3 colonne « Pourquoi (sous la ligne rouge) ») ; les autres critères sont enregistrés vides.
- Google Sheets : POST `no-cors` en `text/plain` vers `apps-script/Code.gs` (`doPost` : ajout/mise à jour par `id` en dernière colonne, suppressions `del`) ; test et vérification de réception par JSONP (`doGet?ids=…` → `have`) : une grimpe ne quitte `SH.q` qu'une fois lue dans la feuille (`r.rx=1`). Script v3 (`VERSION`, `v` dans les réponses) : colonnes rangées par titre, colonnes manquantes ajoutées avant `id` ; l'appli n'envoie `SH_HEAD3`/`shRow3` (avec la cordée) que si `SH.v>=3`, sinon l'ancien format `SH_HEAD` (16 colonnes). **Jamais de prénoms** : `anon()` = hash(clé | classe | prénom), stable entre tablettes ; ou prénom + initiale.
- Synchronisation (comme Relais) : `SY` (clé `escalade.sy`), `syRecords` (clés `cl|id`, `lec|id`, `r|id` sans `rx`, `w`, `c|section`, `pin`), `syScan` (empreintes `hs`, garde-fou disparition massive sauf `SY.mass`), `syFirst` (au 1er contact, ce qui est propre à la tablette ou modifié par rapport à `DEF`/`WDEF` gagne), `syPull`/`syCycle` (`shJ({pull,since,vlist})`), AES-GCM PBKDF2 sel `escalade-eps-sync-v1`. `save()` → `syncSoon()`. Non synchronisés : `CF.grp`, `CF.sea`, `CF.sel`, `SH`.
- Vidéos : clé IndexedDB `v…` = identifiant global ; `VH` inventaire local, `VS` transferts ; `vidUp` (POST `vup` par morceaux de 2 Mo) / `vidDown` (JSONP `vget`) / `vidAuto` / `vidAll` ; script v5 : Drive, dossier « Escalade EPS – vidéos » (`name.i.part` + `name.meta` pour les envois de l'appli ; fichiers vidéo déposés à la main = clé `g_<id Drive>`, lus par morceaux de 1 Mo via l'API Drive avec Range, secours `getBytes()` ; v6 : `verr` renvoyé en cas d'erreur, affiché par l'appli via `VERR`/`vErrTxt`, 3 essais par morceau), `vlist`. `vidMap()` associe les vidéos Drive aux vignettes vides par nom ; `vBar()` explique pourquoi une vidéo manque ; `vidRefs()` ne compte que les blocs `v`/`f` et les vignettes.
- PDF : générateur maison `PDFDoc()` (Helvetica WinAnsi, `pEnc`, largeurs `HWN`/`HWB`), `pdfEleve(doc,name,nom,d)` (bilan si `d` vide, sinon leçon), `pdfFoot`, `pdfOne` (Mes résultats), `pdfLe` (enseignant, un élève ou tous). Script : `autoriserDrive()` à exécuter une fois dans l'éditeur.
- **Pas de noms d'élèves dans le dépôt public** : la version publiée a `const CL0=null;`. La version privée de l'enseignant (fichier local) peut intégrer sa classe dans `CL0`.
- Interface et textes en français, tutoiement des élèves.
- Objectif de la leçon : `L.obj` (phrase saisie dans `lecEdit`), affiché avec le nombre de voies `min` par `objBar()` en haut de l'accueil.
- Tablette de contrôle (`S.t='ctl'`, `ctl()`, tuile enseignant) : une carte par élève de la classe (`CF.sel`) pour aujourd'hui (voies / objectif, meilleure réussite, hauteur max, Tops, cotations tentées, ligne rouge + pourquoi, liste horodatée de toutes les grimpes du jour) ; rafraîchie toutes les 4 s (les grimpes des autres tablettes arrivent par la synchronisation).
- Bilans de la classe : `zipLe(d)` → `Escalade_<classe>_<jj-mm-aaaa>.zip`, un PDF `pdfEleve` par élève de la liste (boutons dans « Aujourd'hui » et dans la consultation d'une leçon). `zip(files,type)` accepte du texte ou des octets.
- Thème « Falaise claire » (fin de `<style>`) : fond pierre `--bg:#e2e5e3`, tuiles d'accueil blanches avec liseré `--c` à gauche et pastille d'icône teintée (`color-mix`), tuiles enseignant liseré foncé + pastille jaune.
- Absents du jour : `CF.ab['<idClasse>|<date>']=[prénoms]` (`setAbs`, `absL`, `isAbs`, `presEl`), réglés depuis la tablette de contrôle (bouton « Absent », section « Absents aujourd'hui » pour les remettre) ; masqués dans le groupe, la cordée et le choix du grimpeur ; PDF « Absent(e) ». Synchronisés (`ab|…`).
- Messages enseignant → élève : `CF.msg=[{id,cl,d,el,t,ts,seen}]` (`msgDlg` depuis une carte de contrôle, messages tout prêts `MSGS`), affichés à l'élève quand il choisit son prénom pour une grimpe (`pickEl` → `showMsgs`, « J'ai lu » remplit `seen`) ; la carte indique « pas encore lu » / « lu à … ». Synchronisés (`m|…`), gardés 30 jours.
- Pédagogie modifiable (`CF.ped`, défaut `PED0`, lecture `PED()`, écriture `pedW`/`pedSet`/`pedDo`, écran enseignant `S.t='ped'` « Situations, cycle et assurage ») : situations d'apprentissage `sit` (titre, consigne, but, réussi si), cycle `cyc` (objectif + situations par n° de leçon, proposé par `cycFor` dans `activate`/`newLe`/`lecEdit`), remédiations `rem` par « pourquoi » (affichées à l'écran « grimpe enregistrée », `remBox`), libellés de l'assurage en 5 temps `b5`, motifs de pénalité `pens` (g = grave). Synchronisé en un seul enregistrement `ped` (seulement si l'enseignant a modifié quelque chose). Leçon : `L.sit` (ids) → accueil (`objBar`, `sitDlg`) et saisie (`sitBox`).
- Permis d'assurer : `CF.bel['<idClasse>|<prénom>']={t5:[0/1×5],pen:[{id,d,ts,t,g,off}],rev}` ; niveau `belLvl` : rouge si `rev`, jaune si pénalité active, vert si les 5 temps sont validés, sinon gris. Onglet « 🪢 Assurage » de la tablette de contrôle (`belGrid`, `tog5`, `penDlg` : faute grave ou 2e pénalité → `rev=1`, `giveBack`, `revoke`), badge `belTag` sur les cartes, `belCard` dans Mes résultats. Permis révoqué : ni assureur ni contre-assureur (`roleIn`, `setRole`, `autoRoles`, `rec`). Synchronisé (`bel|…`).
- Conseils de remédiation : `rem[why].auto` = montré automatiquement à l'élève (par défaut seulement « La voie était trop difficile ») ; sinon l'enseignant le propose. Tablette de contrôle : `helpOf(M)` (sous la ligne rouge, ou 3 dernières voies sans Top) → bandeau « 🆘 À aider » et bouton « 💡 Proposer un conseil » → `msgDlg(n,why)` avec les conseils (`remTxt`, `remFor`) en tête, envoyés comme message.
- Élève sans leçon du jour : écran d'attente `S.t='wait'` (`waitScr`, classe `CF.wcl`), seule la rubrique « Se préparer et assurer » est ouverte ; l'écran s'ouvre tout seul quand la leçon arrive (synchronisation). Plus de création automatique de leçon côté élève (`pickCl`).
- Mode enseignant partagé : `localStorage['eps.teach.until']` (1 h, `hubT`/`hubOn`), posé par la page d'accueil ou par n'importe quelle appli ; l'appli s'ouvre alors en mode enseignant sans code ; « Quitter mode prof » (`quitT`) le coupe partout. Code : `codeOk` accepte `CF.pin` ou le code commun (`relais-vitesse-code-v1`) ; « Code » (`pin()`, 4 chiffres) change les deux.
- Classes en double (même nom créé sur plusieurs tablettes, identifiants différents) : `mergeDupCls()` au démarrage et après chaque synchronisation garde le plus petit identifiant et y rattache élèves, leçons, absents, permis ; `lecFor` retrouve aussi la leçon par nom de classe. Nouvelles classes : identifiant tiré du nom `clsId(nom)` (même calcul dans eps-home.js), identique sur toutes les tablettes.
- Canal de synchronisation `SYC()` : le « Partage entre tablettes » de la page d'accueil (`eps.share.v1`, à défaut la clé de Relais) s'il est réglé — clés préfixées `e:` sur ce script commun (Relais les ignore) — sinon le script d'Escalade (`SH`). `syChan()` remet la synchro à zéro (tout est renvoyé) quand le canal change. Les vidéos passent toujours par le script d'Escalade (`shJ({vlist})`).
- Groupes du jour partagés : `CF.gps=[{id,cl,d,el,ts}]` (synchronisés `gp|`, gardés 30 jours) ; `CF.grp` = groupe choisi sur la tablette (`gid`). Écran groupe : groupes déjà formés (`useG`) ou nouveau groupe (`okG`, modification si `S.gid`). Accueil : « Modifier » / « Changer de groupe ». Saisie, étape 1 : sélecteur de groupe `.gsel`.
- Fin de saisie : « ✓ Terminé : retour au choix du groupe » (`doneG`, vide `CF.grp`). Modifier un groupe : code enseignant (`editG`, sauf mode enseignant). Tablette de contrôle : « ⟳ Rafraîchir » (`ctlRefresh` → `syCycle`).
- Tablette de contrôle, onglet Grimpes : regroupement par groupe du jour (`dayG`) : une ligne de cartes par groupe, séparées par un trait, puis les élèves sans groupe ; bascule « Par groupe / Tous les élèves » (`S.cgv`).
- Messages : aussi montrés une fois au groupe quand un camarade choisit son prénom (`showMsgs`, `m.gseen`/`m.gby`, « transmis par … » sur la carte de contrôle). Prénoms trop longs : points de suspension (`.chip span`). Bouton « Inverser » de la cordée : `.swapb` (grand, jaune).
- Démarrage en mode enseignant : écran « Choisis la classe » (`S.t='tcl'`, `tclScr`, `tPick(id)` → `CF.sel`, leçon du jour activée si elle existe, sinon préparation) ; aussi après « Je suis enseignant » et via « Changer de classe » sur l'accueil enseignant.
- Diagnostic de la synchro : fiche chiffrée `dev|<SY.dev>` (`syBeat`, toutes les 90 s : nom `CF.tab`, nb de grimpes, du jour, en attente, erreur, canal) rangée dans `SY.devs` (jamais appliquée comme donnée) ; tablette de contrôle → « 📡 Tablettes » (`syDevsHTML`), « Renvoyer » (`syResend` : cl/lec/r/ab/gp/m/bel) et « Tout récupérer » (`syRefetch` : `since=0`). Bandeau `syWarn()` si la tablette n'a pas de partage ou utilise encore l'ancien script de Relais (`RELAIS_URL`).
- Pont avec les anciens canaux (`syLegacy`, après chaque `syPull` sur le partage commun) : lit aussi les `e:` de l'ancien script de Relais (`relais-vitesse-sheets-v1` ou `RELAIS_URL` avec la clé commune) et le script d'Escalade (`SH`), n'ajoute que les éléments absents (jamais d'écrasement ni de suppression ; `SY.dk` = clés supprimées, jamais ressuscitées), puis les republie sur le partage commun. Sources injoignables mises en pause 6 h (`SY.lg[sig].dead`).
- Classes regroupées en un seul groupe EPS (ex. TMELEC + TTBMA) : « Classes et élèves » → carte « Regrouper » (`tgRg`, `rgName`, `doRg`) ; `CF.alias[nrm(ancien nom)] = nom du groupe`, synchronisé `al|…` ; `applyAlias()` (appelé en tête de `mergeDupCls`) renomme classes, grimpes `r.cl` et messages, puis la fusion par nom réunit élèves, leçons, absents, permis. Une liste réimportée sous l'ancien nom rejoint aussitôt le groupe.
- 🤖 Bilan de leçon par Claude (enseignant) : carte `aiCard(d)` dans la consultation d'une leçon (`lecView`), bouton « Bilan de la leçon » sur la tablette de contrôle. `aiData(d)` résume la leçon (objectif, situations, critères, groupe, leçon précédente, détail par élève, situations disponibles, séquence) avec des codes E1, E2… (jamais de prénom ; le texte libre des « pourquoi » est coupé) ; `aiBilan(d)` : POST `aiReq` au script commun puis lecture JSONP `aiget` (résultat en cache 6 h côté script, modèle `CLAUDE_MODEL_BILAN`) ; codes remplacés par les prénoms sur la tablette, rangé dans `L.ai` (leçon, synchronisé) ou `CF.aiB`. « Préparer la prochaine leçon » (`aiNext`) préremplit objectif et situations.
- Espace enseignant commun : l'onglet Séquence ouvre d'abord « Choisis la classe » (`S.tcl0` une fois la classe choisie). Vocabulaire : « séquence », jamais « cycle » à l'écran. Bandeau « À aider » de la tablette de contrôle limité à 4 élèves (+ N autres, `S.hpAll`).
- Accueil élève (`home()`, `.tiles.stu`) : « Renseigner une grimpe » et « Cotation » en grand (`main`, 2 colonnes chacune), puis une rangée de petites tuiles (`sm`) : Se préparer et assurer, Mes résultats, Thématiques, Sécurité. L'accueil enseignant garde `TILES`.
- Bulle conseil / message (`msgDlg`) : `.dlg` au-dessus des bandeaux de l'espace commun ; récapitulatif de l'élève à droite (`elRecap` : voies du jour avec heure, corde, cotation, hauteur, pourquoi ; rôles ; permis ; leçons précédentes ; messages déjà envoyés).
- Groupes du jour : « ⇄ Changer de groupe » en grand bouton jaune (`.chg`) ; suppression d'un groupe enregistré (🗑 sur la carte, `delG`) réservée au mode enseignant.
- Situations : « Repos choisis » (s2, remplace « Les trois repos »), « Descente en confiance » (s7, remplace « Chute contrôlée » : jamais s'asseoir dans le baudrier pendant la montée = échec), « Pousser sur les jambes » (s8, `draft:1` = proposition en rouge dans l'éditeur, bouton « ✓ Valider cette situation »). Migration `CF.ped.m3` pour les tablettes dont le contenu a déjà été enregistré (remplace seulement les situations non modifiées).
- AFL / AFLP : `AFLT` (textes officiels CA2, AFL voie générale, AFLP voie pro), chaque situation porte `gt` et `pro` ; `aflTag(x)` affiche le code de la voie de la classe (`voieOf` → `epsVoie`) ; encadré de référence dans l'éditeur. Le CCF (ccf/, gridPro) n'est pas touché.
- Repère de hauteur par leçon : `L.href` = 'ep' (ligne d'épaules, défaut) ou 'bas' (bassin, comme au CCF), choisi dans `lecEdit`, affiché dans l'intitulé du critère hauteur.
- Permis d'assurer (onglet 🪢 Assurage) : liste par élève (`belGrid`) avec filtres (`S.belF`), 5 grands boutons de temps (`.b5s`, vibration), barre de progression, « ✓ Valider les 5 temps » (`all5`). Badge sur le prénom (`belB` dans `chip`) : ✓ vert = assureur autonome, ! jaune, ✕ rouge ; rien en apprentissage.
- 🎨 Indicateurs de performance : `PED().ind` (propositions `PED0.ind`, modifiables, supprimables par `indDel`, remis avec « + ») : `mpd` prises de mains par dégaine, `rp` ratio pieds/mains, `proj` écart au projet (dégaine annoncée `r.ann`), `top` taux de réussite, `perf` indice (cotation × hauteur, comparé à la meilleure leçon précédente), `flu` fluidité (chronomètre de l'observateur `chr` → `r.tt`, `r.ta`). Seuils `v`/`o`, sens `dir` (lo/hi). Leçon : `L.ind` (choix dans `lecEdit`, proposé par la séquence `cyc[i].ind`). Saisie : `indInput()` en tête des critères ; écran « Grimpe enregistrée » : `indBox` ; tablette de contrôle : pastille `.cind` et bordure colorée par carte, résumé `.indsum`.
